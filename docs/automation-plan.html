Where to put automation so it scales across every property and kiosk, eliminates the manual agent work, and uses AI only where AI is actually the right tool. Grounded in the codebase knowledge graph — every claim below maps to real code.

2 · Why the hub is the place

The graph shows a strict hub-and-spoke: every live event already flows through kiotel_web — the kiosk's Socket.IO telemetry, session lifecycle, scans, payments, recording control, agent commands. The PMS is a system of record; the kiosk is an actuator; audio is an observer. Automation belongs where the events are.

Concretely: a new Concierge Brain service that connects to the platform exactly like an agent does — same Socket.IO registration, same RELAY command vocabulary, same scoped auth. To the rest of the system it IS an agent (a tireless one). That single design choice means: zero kiosk changes, zero PMS-core changes, zero new protocols — and per-property rollout is just "assign the robot agent to the property".

4 · Deterministic first, AI where it earns its place

DecisionMechanismWhy
Advance the check-in flow (scan → match → pay → key → receipt) State machine on kiosk telemetry — no AI The RELAY vocabulary + telemetry events make this pure orchestration; must be auditable and repeatable
Money & keys (cash accept/dispense, key cut) Deterministic guards only — AI may never trigger these; brain issues them only from verified state (matched reservation + payment event) Same reasoning as the action-less avatar: no LLM in the actuation path
Ambiguous booking match (typos, OCR noise, same-name guests) LLM ranking over PMS candidates (name + dates + party size), output = a ranked list with confidence, never an action; below threshold → kiosk prompts for confirmation #/phone → agent Fuzzy human-data problem — exactly what LLMs are good at
Guest questions ("when is breakfast?", "where do I park?") RAG avatar: answers grounded in property_rules + property docs; avatar stays TTS-only (action-less) Removes most video escalations without touching the safety design
Guest messages Deterministic triggers send communication_presets; LLM drafts non-standard replies into an approval queue Volume is preset-shaped; the long tail gets a human click
Call-audit review LLM triage over session_ai_audit: cluster, score, surface the 5 sessions worth a human's time; weekly digest Turns an unread firehose into an exception list
Back-office sweeps (no-shows, checkout → housekeeping tasks) Cron rules in PMS — no AI Pure calendar logic; lifecycle enums already model it

7 · Safety rails (non-negotiable)

1. The avatar stays action-less — guest speech never reaches an actuation path (the codebase's own prompt-injection defense; the brain acts only on structured telemetry).
2. LLMs rank and draft; they never directly trigger cash, keys, or status transitions — deterministic guards own actuation.
3. Every brain action lands in session_events with its reasoning — same audit trail as human agents, reviewable in the console.
4. Per-property kill switch: flip the flag, humans are back in the loop instantly.
5. Rotate the hardcoded Deepgram key; all brain/SynXis credentials in env/secrets.

8 · What "scaled" looks like

Today: 1 agent ≈ a few concurrent kiosks, every check-in touched by hand.
After B1: agents supervise; autopilot handles the happy path (target >85% zero-touch check-ins).
After B5: 1 agent supervises a fleet — staffing scales with exceptions, not with properties. Dashboard metrics: zero-touch rate, median check-in time, escalations/day, autopilot-vs-human agreement (from B0 onward), audit flags handled.

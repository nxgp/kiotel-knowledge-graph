SynXis × Kiotel: automated check-in

Integration plan for connecting the SynXis (Aven Hospitality / Sabre) Central Reservation System into the Kiotel platform — so that when a guest walks up to the kiosk, their booking is found and matched automatically, instead of an agent manually looking it up in the PMS and typing the guest name into the session.

Difficulty: MODERATE — the code is ready for it ~6–8 eng weeks Longest pole: Sabre/Aven onboarding

Today's manual flow (what we're eliminating)

Verified from the codebase knowledge graph: there is no shared guest/booking table between the PMS and the platform. The only runtime bridge is the check-in-time name match — the kiosk OCRs the guest's ID, and the platform's guest-name-matcher.ts compares it against t_session_info.guest_name, which is populated per session by a human agent (or the pms-autofill browser extension) after manually finding the booking in the PMS. Every check-in requires a person in the loop.

Start the contract conversation now; it is the schedule's longest pole (typically weeks, not days).

Target architecture

The automated flow

  1. Sync (continuous): SynXis pushes every reservation create/modify/cancel via CRS Reservation Delivery → synxis-sync maps it into the PMS reservations table (new columns: crs_confirmation_number, crs_source; booking_source = channel_manager). Nightly REST Retrieve sweep reconciles misses.
  2. Guest arrives: kiosk detects approach, scans ID, OCR extracts the name — exactly today's pipeline, unchanged.
  3. Auto-match: the platform's matcher calls the new PMS lookup API with (name, today's date ± window). One confident hit → session auto-populated, reservation → pre_checked_in. Ambiguous or zero hits → kiosk asks for confirmation number / last 4 of phone → retry → only then escalate to an agent.
  4. Check-in completes: payment + key dispensed → platform notifies PMS → reservation → checked_in, folio opens. (Later phase: propagate status back to SynXis via Modify Reservation.)
  5. Audit + metrics: every auto-match decision logged to session_events; auto-match rate, fallback rate, and time-to-check-in appear on the ops dashboard.

Risks & mitigations

RiskMitigation
Sabre onboarding/certification slips Start Phase 0 now; build Phases 1–3 against recorded HTNG/REST fixtures — the CERT environment is only needed for certification, not development
Reservation delivery is SOAP/HTNG Isolate XML behind the mapper; the rest of the PMS never sees SOAP. REST Reservation Services covers retrieve/backfill.
Same-name / ambiguous guests Never auto-match below threshold: confirmation number or phone last-4 prompt at the kiosk, then agent fallback (which is just… today's flow)
PII (names, contact data) now flows PMS → platform Scoped lookup returns the minimum fields (name, confirmation, room-type, status); existing token+CIDR pattern; audit every lookup. Also: rotate the hardcoded Deepgram key and keep SynXis credentials in env/secrets from day one.
Sync drift (missed deliveries) Nightly REST reconciliation sweep + Change Discovery checkpoint; alert on delta

Success metrics (wire into the ops dashboard)

Auto-match rate (target: >85% of check-ins need no agent) · median time-to-check-in · agent escalations per day (should fall from ~100% of check-ins to exceptions) · sync freshness (CRS event → PMS row latency) · reconciliation delta (missed reservations per night).
